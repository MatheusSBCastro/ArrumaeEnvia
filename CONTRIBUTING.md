# Contribuir

São bem-vindas melhorias na clareza dos materiais, acessibilidade dos currículos, tratamento de portais e ferramentas de acompanhamento.

Use dados fictícios em exemplos, testes, issues e capturas. Não anexe currículo real, documento pessoal, senha, cookie, sessão ou respostas de outra pessoa. Relate problemas no fluxo descrevendo portal, etapa e resultado observado, sem informações identificáveis.

Para alterações de código:

1. Explique o comportamento que deseja corrigir ou acrescentar.
2. Preserve a separação entre gerar arquivos localmente e operar sites pelo agente.
3. Inclua validação relevante para o comportamento alterado e rode os testes do README.
4. Atualize os comandos documentados se o uso mudar.

Evite mudanças que gerem afirmações profissionais sem confirmação, escondam custos, capturem credenciais ou marquem tentativas como envios bem-sucedidos. Novas integrações devem declarar suas dependências e como verificar o resultado. Não grave seletores de uma única versão de formulário como garantia de funcionamento universal.

Antes de publicar, confira `git status --short` e o diff. Arquivos em `.local/` não devem aparecer. Se dados pessoais já foram versionados, ignorar o caminho não remove o histórico: trate a remoção antes de compartilhar.
